# 重要信息

更新时间：2026-08-14

## WebGPU Clouds 阴影数据流

```text
CloudShadowNode（生成 BSM）
  ├─ CloudsMarchNode：云内部自阴影，读取 maxOpticalDepth + tail
  └─ CloudsNode.getSunTransmittanceNode()
       └─ AerialPerspectiveNode：物体表面太阳直射光，仅读取 maxOpticalDepth
```

- `CloudsNode` 是 BSM 生产者与消费者之间的公开门面，表面光照不应直接依赖 `CloudShadowNode` 内部实现。
- `AerialPerspectiveNode.sunTransmittanceNode` 是可选工厂；为空时行为与原 WebGPU 版本完全一致，存在时只乘到太阳直射照度，天空间接照度和月光不受影响。
- 表面阴影需要 Aerial Perspective 接收 normal attachment；Basic 使用 MRT 输出 `diffuseColor` 和 `normalView`。
- 表面阴影的相机 view/projection/near 使用 `CloudsNode` 自有显式 uniform。不要替换成名为 `viewMatrix` 的相机 `ReferenceNode`，否则会与全屏通道绑定冲突并生成非法 WGSL。
- BSM cascade count 和 shadow sample count 是着色器常量；切换 quality preset 后必须标记后处理节点需要重建。
- Basic 默认保持静态和隐藏接收盒子，便于稳定比较；动画与 `showShadowReceiver` 都通过 Storybook controls 显式开启。
- `CloudShadowNode` 的三维计算核必须用 `computeKernel()` 创建；禁止把 `compute(1, ...)` 当成稍后可覆盖的默认尺寸，否则 TSL 会永久加入只允许首个 invocation 执行的 count 守卫。
- 2026-08-14 当前状态：march/current BSM 已恢复有效数据；temporal resolve A/B 仍全零，尚未完成。Custom Layers 暂时通过关闭 temporal shadow pass 读取 current BSM。

## WebGPU Clouds 自定义云层数据流

```text
CloudLayers（层参数 + RGBA 通道顺序）
  └─ CloudsNode.setCloudLayers()
       ├─ CloudsMarchNode.localWeatherChannels
       ├─ CloudShadowNode.localWeatherChannels
       ├─ layer uniforms
       └─ resetHistory()
```

- 云层数值参数通过共享 uniform 更新；天气通道 swizzle 会进入着色器节点图，必须同步到主步进和云影步进。
- `storybook-webgpu/src/clouds/Clouds-Basic.tsx` 是可配置场景入口：默认保持原 ECEF Basic 行为，`localFrame` 仅供需要位置 controls 的示例启用。
- Custom Layers 在 North-Up-East 局部坐标中保持相机与云层的相对关系，位置 controls 只更新世界到 ECEF 变换，因此无需在每次经纬度变化时重建相机。
- `AtmosphereContext.matrixECEFToWorld` 必须使用 `matrixWorldToECEF.invert()`；North-Up-East 矩阵带有 ECEF 平移，严禁改回只适用于纯旋转的 `transpose()`。
- Custom Layers 通过 `temporalShadows={false}` 使用确定性的当前帧 BSM，并将 Story 的 `temporalUpscale` 默认设为 `false`；这是展示页的稳定性选择，不改变 Basic 默认策略。
